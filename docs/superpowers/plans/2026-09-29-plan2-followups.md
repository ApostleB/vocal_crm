# 계획 2 실행 후 남은 항목 (계획 3 작성 시 반영)

계획 2(지점 이동·엑셀)는 2026-09-29 main 에 완료되었다. 테스트 38개 파일 149개 통과, 빌드 성공.
실제 앱을 띄워 가져오기·내보내기 흐름 7개도 점검했다. 파일 대화상자는 Playwright `_electron` 으로 Main 에서 대체했고, 모두 통과했다.
계획 1 후속 문서의 "계획 2 시작 전 store 보강" 3개 항목은 계획 2 Task 1 에서 처리했다.

## 계획 3 에 반드시 넣을 것

- **가져오기 전 자동 백업:** `transfer.applyVcrm`·`excel.applyRoster` 적용 직전에 백업한다(설계 5.8).
  - 지금은 가져오기와 명단 등록을 되돌릴 방법이 없다.
  - 백업이 들어가기 전에는 트레이너에게 배포하지 않는다.
- **E2E 방식:** Playwright `_electron.launch` 와 `app.evaluate(({ dialog }) => …)` 로 저장·열기 대화상자를 대체하는 방식이 계획 2 확인에서 잘 동작했다. 계획 3 의 E2E 도 이 방식으로 쓴다.

## 사용자가 계획 그대로 두기로 한 것

- **다른 고객의 기록 id 와 겹치는 합치기**
  - 상황: 같은 파일을 한 번은 고객 X 로 "신규 추가"하고, 다른 고객 Y 로 "합치기"한다.
  - 결과: 합칠 때마다 수업이 새 id 로 다시 복사된다. 반대로 수강권과 이력은 이미 있는 id 로 보고 건너뛴다.
  - 드문 경우라 사용자가 그대로 두기로 했다(Task 5).
  - 다시 손본다면 "다른 고객 소유 id 는 이미 옮겨진 것으로 보고 건너뛰기"로 기록 종류마다 규칙을 통일한다.

## 보강 후보 (급하지 않음)

- **명단 머리글 확인:** 1행이 양식 머리글과 같은지 보지 않는다. 다른 명단 파일을 열면 열이 조용히 엉뚱한 칸에 들어간다.
- **"이동해 옴" 이력 중복:** 같은 파일을 다른 날 다시 합치면 이 이력이 한 줄 더 생긴다. 판단 기준을 파일의 `exportedAt` 으로 바꾸면 막을 수 있다.
- **.vcrm 검증 강화:** 생성·수정 시각을 `z.iso.datetime()` 으로 검사하고, 날짜 형식(`2026-13-45` 같은 값)도 거른다.
- **고객 엑셀 `휴강 종료 예정일`:** 설계는 "모든 기본 항목"인데 이 열이 없다.
- **엑셀 중복 클릭:** 고객 선택 창의 `엑셀로 저장` 버튼에 로딩 상태가 없어, 두 번 누르면 저장 창이 두 번 뜰 수 있다.
- **명단 파일 안의 중복:** 같은 파일 안에서 이름이나 연락처가 겹치는 행은 힌트가 없다.
- **합치기 세부 규칙**
  - 다른 고객에 이미 걸린 별칭은 버려진다.
  - 한 파일 안에 같은 제목 목표가 둘 있으면 둘 다 들어간다.
- **테스트 보강 후보**
  - 합치기의 다른 고객 소유 수업·목표 분기
  - 합친 뒤 공통메모가 두 번 붙지 않는지
  - 공백 칸만 있는 명단 행
  - .vcrm 저장 취소 화면 흐름
  - 여러 명 내보내기 순서
- **코드 정리 후보**
  - `blankToNull` 재사용
  - `today()` 도우미 중복
  - `markMoved: move` 이름 가림
  - 고객 표시 문구(이름 · 연락처) 중복
  - `as string` 캐스트
  - 오류 문구를 React key 로 쓰는 곳
- **표기 차이:** 회차 기록 시트 열 이름이 `수강권 차감` 인데 설계는 `차감 여부` 다.
- **커밋 공동 작성자 줄:** 최종 수정 커밋 3개(`2fe7d85`, `09c091e`, `0ab1368`)는 다른 모델명으로 되어 있다. 히스토리는 다시 쓰지 않는다.
